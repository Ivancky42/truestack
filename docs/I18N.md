# Internationalisation (next-intl)

English is the default, unprefixed locale. Bahasa Malaysia lives at `/ms`, Simplified Chinese at `/zh`, Russian at `/ru`. next-intl 4.14 handles routing and messages; this file is the contract for anyone adding or translating copy.

## Routing rules

- Locales: `en` (default), `ms`, `zh`, `ru`. `localePrefix: "as-needed"` so every existing English URL stays unchanged.
- `localeDetection: false` and `localeCookie: false`. The proxy never redirects on `Accept-Language`. A dismissible suggestion bar under the header offers the browser language when it differs from the page.
- Choice is stored in our cookie `ts_locale` (1 year). Dismissal is `ts_locale_hint=dismissed` (30 days). Cookie writes are **client-only**.
- **There is no `app/layout.tsx`.** `app/[locale]/layout.tsx` is the root layout. A passthrough root layout would make every route dynamic — do not add one.
- **Never call `headers()` or `cookies()` in server components.** All marketing routes must stay statically prerendered (`●`). Cookie read/write lives in `lib/i18n/cookies.ts` and runs in client components only.
- Navigation uses `@/i18n/navigation` (`Link`, `usePathname`, `useRouter`, `redirect`, `getPathname`). `usePathname()` returns the unprefixed path, so `startsWith("/services")` checks keep working.
- English-only surfaces (legal pages only — privacy, terms, PDPA, cybersecurity): body stays English under `/ms`, `/zh` and `/ru`, with `robots: noindex` and a canonical pointing at the English URL.
- Insights: article bodies stay English (Sanity). Chrome, FAQ and metadata are localized. `/insights`, `/ms/insights`, `/zh/insights`, `/ru/insights` and each published slug are indexable, emit a full hreflang set plus a self-canonical, and appear in `app/sitemap.ts` for all four locales.
- hreflang is emitted in two places from one helper (`hreflangAlternates` in `lib/i18n/config.ts`): per-page `<link rel="alternate">` via `localizePageMetadata` and `<xhtml:link>` in `app/sitemap.ts`. Keys: `en`, `ms`, `zh-Hans`, `zh-CN`, `ru`, `x-default` (→ English). next-intl's `Link` header is disabled (`alternateLinks: false`) so the two sets never disagree. `og:url` always equals the canonical. `og:locale` is `en_MY` / `ms_MY` / `zh_CN` / `ru_RU`; localized pages also emit `og:locale:alternate` for the other three.
- Known limitation — 404s: `app/[locale]/[...rest]` calls `notFound()`, which Next renders through its error shell: status 404, automatic `noindex`, localized `NotFound` body hydrated on the client, `<title>` = the locale's `Common.siteTitle`. `not-found.tsx` cannot export metadata and `global-not-found.tsx` has no locale, so this is accepted.

## Message conventions

- One namespace per JSON file under `messages/{en,ms,zh,ru}/`. File name is kebab/camel; the exported object key is the PascalCase namespace (`header.json` → `Header`).
- `en` is the source of truth. `lib/i18n/messages.tsx` statically imports every English JSON file and the `messages/{ms,zh,ru}/index.ts` barrels, then deep-merges the locale overlay onto English so missing keys fall back to English during rollout (never show raw keys). Do not read `messages/` from the filesystem at runtime — Vercel will not reliably trace those directories into the serverless bundle.
- `PageMessages` always includes `Common` alongside the page namespace. A nested `NextIntlClientProvider` **replaces** parent messages — do not omit `Common`.
- Data arrays keep structure, icons, hrefs and accents in TSX. Text is read by stable keys: `t(\`solutions.${key}.title\`)`.
- Muted-second-sentence headings use `t.rich("title", { muted: (chunks) => <span className="text-muted-foreground">{chunks}</span> })`.
- Each file carries a root `_status` field (`source` for English, `ai-draft` or `reviewed` for translations). The loader and `pnpm i18n:check` ignore `_status` when merging and comparing keys.
- Chrome namespaces loaded in the locale layout: `Common`, `Header`, `Footer`, `Banner`, `NotFound`.
- Run `pnpm i18n:check` after any message edit. It fails on missing keys, ICU `{name}` mismatches, and metadata length violations. Extra keys and empty strings are warnings.

### Adding a namespace

1. Create `messages/{en,ms,zh,ru}/<file>.json` with the same key set (`en` is source; `ms`/`zh`/`ru` `_status: ai-draft` is fine).
2. Import the English file in `lib/i18n/messages.tsx` and add it to the `EnMessages` intersection **and** the `englishMessages` merge.
3. Import the same file in `messages/ms/index.ts`, `messages/zh/index.ts` and `messages/ru/index.ts` and pass it to `namespaces(...)`.
4. Load the namespace on the page via `getTranslations("Ns")` / `PageMessages namespaces={["Ns"]}`.

Work listing and each `/work/[slug]` case study are localized via the `WorkStudies` namespace (cards, detail bodies, FAQ, metadata). `WorkChrome` is page chrome only.

### Copy change or new page (do this automatically)

Agents and humans ship **all four locales in the same change**. Do not leave `ms`/`zh`/`ru` for a follow-up.

| Change | What to do |
|---|---|
| Edit existing copy | Change the English key, then the same key in `messages/ms/`, `messages/zh/` and `messages/ru/`. Same path, same array length, same ICU `{name}` / `t.rich` tags. |
| New page | New namespace (steps above) + `localizePageMetadata` (not `english-only`) + localized JSON-LD + sitemap entry **outside** `ENGLISH_ONLY_PATHS`. |
| Body links | `[[label|/path]]` — translate the label, never the href. |
| Structure vs text | Slugs, hrefs, icons, image `src` stay in TS. Reader-facing strings live in messages. Reference: `lib/work-case-studies.ts` + `messages/*/workStudies.json`. |

Cursor loads this as an always-on rule (`.cursor/rules/truestack-i18n.mdc`) and the `truestack-i18n` skill.

### What stays English

## Tone for translators

- Formal Bahasa Malaysia, second person **anda** (not *kau* / informal *kamu*). Malaysian BM, not Indonesian.
- Simplified Chinese, business register **您**.
- Formal Russian, second person **вы** (never *ты*). Never use «ростовщик» for a licensed money lender — use **лицензированный заимодавец**.
- Benefit-first, concise, no hype words (seamless, cutting-edge, world-class, revolutionary, robust, leverage, empower).
- ™ on the first prominent product mention per page, then plain CamelCase.
- Malaysian/British English spelling in the source (`licence`, `organisation`). Do not “fix” URL slugs — they stay American (`/services/digital-license`).
- Name Malaysian realities precisely. If a regulatory term is not in this glossary, stop and ask.

## Language switcher and suggestion bar

- Header desktop: globe + short label (EN / BM / 中文 / RU) + chevron. Mobile sheet: segmented `EN | BM | 中文 | RU` above the CTA.
- Selecting a language writes `ts_locale` and `ts_locale_hint`, then `router.replace` on the same pathname and query string.
- The suggestion bar mounts after hydration. It stays hidden when either cookie exists, when `navigator.languages` has no supported tag, or when the first supported tag matches the current locale. It is symmetric (an English browser on `/ms` is offered English).
- Do not put `data-nav-theme="dark"` on the bar. A visible light bar under the header may keep chrome light over a dark hero; that is acceptable.

## Russian typography

Rethink Sans and Newsreader have no Cyrillic glyphs. Inter is loaded with `cyrillic` + `cyrillic-ext` subsets. On `html[lang="ru"]`, display heading variables (`--font-rethink-sans`, `--font-newsreader`) retarget to Inter so `/ru` headings do not tofu. Arabic on TrueSyariah still uses Noto Naskh.

### China reachability (audit of `/zh` and `/zh/truekredit`, do not strip)

Fonts are self-hosted via `next/font` (Rethink Sans, Inter, Geist Mono, Newsreader, Noto Naskh, Noto Sans SC) — no `fonts.googleapis.com` request at runtime. Live external hosts on those pages: `d0.awsstatic.com` (Powered-by-AWS badge; likely slow or blocked in mainland China — keep, or later host the badge locally), `cdn.sanity.io` (only if Insights images render; likely slow — keep, move to a China-reachable host only if it becomes a production problem). Outbound links only (not render-blocking): LinkedIn, GitHub, Crunchbase, Capterra, aws.amazon.com, client sites. No Google Analytics / gtag, Google Maps, YouTube, or Vercel Analytics / Speed Insights on these routes. First-party `/_next` and `truestack.my` / `developers.truestack.my` are fine.

## Manual discoverability (no code hooks)

These are operator steps, not engineering work:

1. Register the site in [Baidu Webmaster Tools](https://ziyuan.baidu.com/) and submit `https://www.truestack.my/sitemap.xml`.
2. Register the site in [Bing Webmaster Tools](https://www.bing.com/webmasters) and submit the same sitemap.
3. Optional later: a Baidu verification meta tag if they require it after registration.

## Checks

```bash
pnpm i18n:check
pnpm lint
pnpm build
```

`pnpm i18n:check` compares `messages/ms`, `messages/zh` and `messages/ru` against `messages/en` when those directories exist, and skips them when they do not.
